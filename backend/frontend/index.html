    Process

    Most of my projects are built in groups, so I am used to working in sprints with fixed deadlines and regular status meetings, planned in Jira with Scrum.

    1. Plan: break the problem into small tasks and agree on who owns what.
    2. Build: write the code in small steps with Git, one branch per feature.
    3. Test: add unit tests along the way and run them in a CI pipeline.
    4. Ship: package the application with Docker, so it runs the same everywhere.

    I take ownership of my own part, but I also step in where the group needs extra help. As a teaching assistant I read and debug other people's code every week, which has taught me to explain clearly why something does not work.

    About

    I am a 4th-semester Software Engineering student at Aarhus University (BSc, expected 2028). I grew up in the Danish minority in Flensburg, Germany, and speak Danish, German and English.

    I have built everything from an Arduino-based lighting system to an encrypted mesh network in C++ between Raspberry Pis. Right now I am working on a multiplayer dungeon crawler in Unity and this website: a .NET 10 Web API with its own SQL database and a JavaScript frontend, running in two Docker containers.

    The backend is what interests me most: designing APIs, handling data and making the different components work together.

    Alongside my studies I am a teaching assistant in object-oriented programming in C++. Before that I worked as an app tester at 3appy, where I learned to pay close attention to details and report bugs clearly.

    Skills: C, C++, C#, Python, JavaScript, HTML, SQL, React, Git, Docker, .NET, Unity, Jira, Scrum.
